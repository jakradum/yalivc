## Auth — Portal (`portal-session` cookie)

- OTP flow via `/api/portal-auth/route.js`
- Page-level verification: `src/lib/session.js` (Node.js `crypto`, server components only)
- Standard page pattern:
  ```js
  const cookieValue = cookieStore.get('portal-session')?.value;
  const userEmail = cookieValue ? verifySession(cookieValue) : null;
  if (cookieValue && userEmail === null) redirect('/partners/sign-in');
  ```
- `redirect` must be imported from `next/navigation`, NOT `next/headers`
- Trusted domains (bypass portalUser lookup): `@yali.vc`, `@florintree.com`
- Access condition: `portalUser` Sanity doc with `lpPortalAccess == true` OR `(!defined(lpPortalAccess) && isActive == true)`
- Kill switch: `noAccess: true` on `portalUser` blocks access even for trusted domains

## Quarterly Logic

- Indian fiscal year quarters: Q1=Apr–Jun, Q2=Jul–Sep, Q3=Oct–Dec, Q4=Jan–Mar
- Fiscal year label: "FY26" = April 2025 – March 2026
- All quarter period logic lives in `src/lib/quarterly-utils.js` — check here before writing any date/quarter handling
- Company detail pages show investment rounds filtered to the **current quarter only** — use `filterInvestmentRounds(rounds, quarterEndDate, nextQuarterEndDate)` from `quarterly-utils.js`
- FMV/metrics fallback: only use past quarters, never future — use `getMostRecentPastQuarterData()` not `latestQuarter` or `quarterlyUpdates[0]`

### Company section HTML structure (`generateQuarterlyPdf.js`)

Each company renders as a `<table class="company-ab-table">` with `<thead>` (repeating page header) and `<tbody>`. The tbody uses a **split `<tr>` structure**:

1. **First outer `<tr>`** — all narrative content in a single `<td>`:
   - Company heading + logo
   - Snapshot table (`<table class="report-table">`) with investment summary
   - About text, current quarter update, all previous quarter updates
   - Section divider (crimson `<div class="section-divider">`) at the bottom

2. **Individual `<tr>` per round detail row** — generated by `flexTr()` helper:
   - One `<tr>` for the "Investment round details" heading
   - One `<tr>` for the column header row (Stage, Series A, Series B…)
   - One `<tr>` per data field (Pre-money valuation, Total round size, etc.)
   - One `<tr>` for the footnote

3. **Individual `<tr>` per financial row** — same pattern for Financials / Key matrix

4. **Spacer `<tr>`** — 80px height to leave room for the CONFIDENTIAL footer

**Why this structure:** Chrome's print engine treats `<tr>` elements as atomic — it won't break within a `<tr>` even with `break-inside: auto`. Putting large narrative blocks (prevQ updates) in separate `<tr>` rows causes gaps: if a row doesn't fit on the current page, Chrome pushes the entire row to the next page, leaving empty space. Keeping ALL narrative in one `<tr>` lets Chrome break within the `<td>` at page boundaries freely. Keeping each round detail row as its own `<tr>` means Chrome breaks between rows at the page boundary without any block-level optimisation pushing the whole table to the next page.

**`flexTr(cells, options)` helper** (defined inside the company map callback):
- `cells`: array of strings — first element uses `width:34%`, rest use `flex:1`
- Options: `topBorder` (2px crimson top), `bottomBorder` (`'thick'`=2px crimson / `'thin'`=1px #d4d0cc / none), `isHeader` (crimson bold text)
- Returns a `<tr><td style="…"><div style="display:flex;">…</div></td></tr>` string

### Page numbering (`pdfRequestHandler.js`)

After `page.setContent()`, a `page.evaluate()` script:
1. For each `[data-toc-page]` span in the TOC, looks up the target element by ID and sets `span.textContent = Math.floor(el.getBoundingClientRect().top / 1123) + 1`
2. For each `.page-number` badge, does the same on the nearest `.page` / `.company-ab-table` / `.media-page-table` ancestor

`getBoundingClientRect().top` gives the exact Y position in the rendered layout. Since the HTML body is fixed at `width: 794px`, the screen layout matches the PDF layout exactly — no height estimation, no formula, no thead-height correction needed.

`data-toc-page` attributes in the TOC `<span>` elements reference section element IDs (`section-cover-note`, `section-fund-summary`, `section-portfolio-investments`, `section-portfolio-updates`, `section-fund-fin`, `section-pipeline`, `section-media`, `section-contact`).
